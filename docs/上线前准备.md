# 上线前准备

从"个人开发环境"切到"公司正式环境"要做的事，以及上线本身要注意的点。按**上线当天照着做**的粒度写，操作步骤可直接照抄。

---

## 0. 先理解：这个项目有三层东西，处理方式完全不同

| 东西 | 存在哪里 | 上线时怎么办 |
|---|---|---|
| 界面上的数据（门店、服务、广告、订单） | 云端数据库 | 结构重建，业务数据不迁 |
| 云函数（`cloudfunctions/`） | 云环境里 | 重新部署，**代码一个字不用改** |
| 小程序页面代码（`miniprogram/`） | 开发者的电脑 | **只改 3 个配置项** |

换句话说：换环境不是"把项目重写一遍"，而是"在新账号下把同样的东西铺一遍，再把 3 个字符串改掉"。

---

## 1. 为什么不能直接把个人环境搬过去

- 微信云开发的「环境共享」官方要求**同一主体**——A 小程序的环境只能共享给同主体下的其他小程序/公众号。
- 个人号和企业号是**两个不同主体**，这条路不存在。
- 云环境与 AppID 绑定，**不支持解绑，也不支持跨账号转移**。

所以"把个人环境换成公司的"= **在公司 AppID 下新建一个环境，把结构和代码铺过去**。

## 2. 微信公众平台：账号级设置（不能迁移，只能重做）

这些设置属于**账号本身**，跟着账号走，换账号就要重做一遍。好消息是内容可以照抄，建议**开发期就把这些内容记录下来**，上线时直接粘贴。

### 2.1 补全小程序基本信息

路径：登录 [mp.weixin.qq.com](https://mp.weixin.qq.com) → 设置 → 基本设置

新号会提示"请先补充小程序基本信息"，点「前往填写」，补齐：

- 小程序名称、头像、简介
- **服务类目**（主体不同可选范围不同，公司主体可选类目比个人多）

> 类目选得不对，后面有些能力（比如手机号快速验证）会不让你用。

### 2.2 配置《用户隐私保护指引》⚠️ 最容易漏

路径：设置 → 基本设置 → 往下滚 → **服务内容声明** → 用户隐私保护指引

**本项目需要声明的收集项**（少一项，对应的接口就会直接失败）：

| 用在哪 | 需要声明的项 |
|---|---|
| 注册登录 | 手机号 |
| 资料页 | 昵称、所在园区、性别 |
| 聊天 | 用户发布的内容（UGC） |
| **广告素材上传、订单照片、跑腿证件照** | **相册（仅写入）权限 / 摄像头** |
| 跑腿认证 | 真实姓名、学号、身份证与学生证照片 |

> **踩过的坑**：开发期加"上传广告素材"功能时，代码加了但隐私声明没跟着补，结果 `wx.chooseMedia` 一直返回 `api scope is not declared in the privacy agreement`。**任何新增"选图片/拍照"的功能，都必须回到这里补声明。**

### 2.3 微信认证（决定能不能拿手机号）

「手机号快速验证组件」只对**非个人主体且已认证**的小程序开放。个人主体拿不到，这也是开发期必须靠 `DEV_LOGIN` 开关登录的原因。

公司账号完成认证后，登录页的手机号按钮才会真正可用。

### 2.4 订阅消息（可选，但建议上线前评估）

现在"新订单""新客户注册"这类提醒是**前端轮询**（约 15 秒一次），客户端一多会持续消耗云函数调用量。要改成推送，需要在 公众平台 → 功能 → 订阅消息 里选模板并让用户主动授权。**不阻塞上线，但人多之前建议做。**

## 3. 云环境：在公司账号下重建

### 3.1 建环境

开发者工具 → 云开发 → 新建环境，拿到环境 ID。

> 环境名只能用小写字母、数字、中划线；地域选国内。

### 3.2 建集合

共 **12 个**：

```
users / phoneClaims / stores / conversations / messages / notifications
notificationReads / services / banners / orders / settings / auditLogs
```

**权限全部选「所有用户不可读写」**（老版控制台叫「仅管理端可读写」）。这是本项目的核心安全设计——小程序端绝不直连数据库，所有读写都走 `api` 云函数。权限选错等于把数据库敞开。

### 3.3 建索引

**12 组**，名称和字段都必须一致（名称可以自己起，但建议照抄，方便和文档对照）：

| 集合 | 索引名称 | 字段（排序） |
|---|---|---|
| users | `storeId_role_createdAt` | storeId↑ + role↑ + createdAt↓ |
| users | `createdAt` | createdAt↓ |
| stores | `enabled_createdAt` | enabled↑ + createdAt↑ |
| conversations | `customerId_lastMessageAt` | customerId↑ + lastMessageAt↓ |
| conversations | `storeId_lastMessageAt` | storeId↑ + lastMessageAt↓ |
| messages | `roomId_seq` | roomId↑ + seq↓ |
| notifications | `storeId_createdAt` | storeId↑ + createdAt↓ |
| services | `enabled_createdAt` | enabled↑ + createdAt↓ |
| banners | `enabled_weight` | enabled↑ + weight↓ |
| orders | `customerId_createdAt` | customerId↑ + createdAt↓ |
| orders | `storeId_createdAt` | storeId↑ + createdAt↓ |
| orders | `delivery_status_createdAt` | delivery↑ + status↑ + createdAt↓ |

`settings` 只有一条配置记录，不需要索引。

> 云数据库的硬规矩：查询里用到的排序字段组合必须有对应索引，否则查询直接被拒。少一组，对应页面就查不出数据。
> 集合自带的 `_id_` 和 `_openid_1` 是系统索引，不用管；索引是异步创建的，状态变成「已完成」才生效。

### 3.4 建议：用脚本批量建，别手点

手点 12 个集合 + 12 组索引大概半小时，而且容易漏。更稳的做法是写一个初始化脚本：

- 用腾讯云开发的 Node SDK（`@cloudbase/manager-node`）或 CLI（`@cloudbase/cli`）
- 读仓库里的 `database/collections.json` 作为唯一输入（集合清单和索引定义都在里面）
- 一条命令把集合和索引全部建出来，建完打印一份"应建 / 实建"的对照，便于核对
- **密钥只从环境变量读，不写进代码、不进 Git**（腾讯云控制台生成，给它数据库操作权限即可）

这份脚本**目前还没写**——因为接口和清单还可能变。等公司账号确定下来再写，到时 `collections.json` 就是现成的输入。

### 3.5 部署云函数

开发者工具左侧右键 `cloudfunctions/api` → 「**上传并部署：云端安装依赖**」。

> 一定选「云端安装依赖」，不要选「所有文件」——本地没有 `node_modules`。

### 3.6 环境变量

云开发控制台 → 云函数 → `api` → 配置 → 环境变量：

**公司生产环境：一个都不要设。**

| 变量 | 开发期 | 生产环境 |
|---|---|---|
| `DEV_LOGIN` | `1` | **不设** |
| `BOOTSTRAP_ADMIN_OPENID` | 你的身份 | **不设**（首个管理员改用下条办法） |

### 3.7 首个管理员怎么来

生产环境不用 `BOOTSTRAP_ADMIN_OPENID`，改用官方推荐的做法：

先正常注册一个账号 → 由有云控制台权限的人在 `users` 集合里找到这条记录，只把 `role` 从 `customer` 改成 `admin` → 该账号重新登录后出现管理中心。

### 3.8 导入门店种子数据

数据库 → stores 集合 → 导入 → 选 `database/stores.seed.import.json`。

> 两重要求：**文件名必须是 `.json` 后缀**（`.jsonl` 会被拒），**内容必须是 JSON Lines**（一行一个对象）。仓库里的 `stores.seed.json` 是数组格式，别直接导它。

## 6. 数据：什么能迁、什么不能迁

| 数据 | 迁不迁 | 原因 |
|---|---|---|
| 集合结构、索引 | **必须重建** | 结构不是数据 |
| 门店 stores | 重新导入 | 种子数据，重新来更干净 |
| 服务 services | 重新录入 | 数量少 |
| 用户 users | **不要迁** | openid 变了，迁过去全是死账号 |
| 聊天 conversations / messages | **不要迁** | 同上，且是测试内容 |
| 手机号占用 phoneClaims | **不要迁** | 同上 |
| 通知 notifications / notificationReads | **不要迁** | 测试噪音 |
| 订单 orders | **不要迁** | 测试数据 |
| 审计日志 auditLogs | **不要迁** | 测试噪音 |
| 云存储文件（广告素材、证件照） | 不要迁 | 证照审核完就删了；广告素材重新传 |

**为什么用户迁不了**：`openid` 由 AppID 决定，换 AppID 后同一个人的 openid 完全不同；`unionid` 只在同一开放平台账号下才一致，个人号和企业号不共用开放平台账号。跨主体**没有可靠手段**把"同一个真人"关联起来。

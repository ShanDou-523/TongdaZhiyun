# 本地演示与功能验收

## 如何进入

1. 在微信开发者工具重新编译项目，默认从登录页自动进入「功能演示」。也可添加编译条件，页面选择 `pages/demo/index`。
2. 点击测试身份直接进入，不需要手机号、密码、云数据库或部署云函数。
3. 业务页面顶部显示「本地演示 · 数据仅存本机」，点击「切换身份」返回选择页。
4. 点击「重置本机演示数据」恢复初始数据；会清除本机演示修改，不影响云端或其他本地存储。
5. 「进入云端登录 / 联调」退出本地身份，进入个人云环境流程。

当前 `miniprogram/config.js` 中 `demoEnabled: true`。演示仅允许开发版、体验版；正式版及无法识别的运行环境均禁用。需要关闭时改成 `false`。

本次单店演示使用新的本地数据空间；重新编译后直接显示一家门店。上一版双店演示数据保留但不再读取，之前的演示修改不会带入这一版。

## 初始测试身份

| 身份 | 归属 | 主要验证内容 |
|---|---|---|
| 客户 A | 门店 | 编辑资料、联系门店、35 条聊天历史 |
| 客户 B | 门店 | 同店另一客户视角与私人会话隔离 |
| 店员小林 | 门店 | 客户列表、回复、注册通知 |
| 店员小周 | 门店 | 同店第二名员工的通知已读隔离 |
| 平台管理员 | 全平台 | 门店管理、账户分配、服务/广告维护、启停和只读审计 |

另外准备了门店的 24 名示例客户，共 26 名客户、26 个会话，便于测试分页。手机号字段是模拟编号，不代表经过微信验证或可以拨打的真实手机号。

## 按顺序试一轮

| 步骤 | 操作 | 应看到的结果 |
|---|---|---|
| 1 | 客户 A 进入「我的」，修改昵称和园区 | 保存后再次进入仍保留 |
| 2 | 客户 A 联系门店，发送“我要咨询洗护” | 消息出现；查看更早消息能加载完整历史 |
| 3 | 切换店员小林，打开对应会话并回复 | 能读到客户消息，客户 A 切回能看到回复 |
| 4 | 店员小林加载更多客户和更多会话 | 能超过 20 条，会话自动刷新后保留加载范围 |
| 5 | 演示入口创建测试客户，选择门店 | 进入新客户首页，选择页出现新账号 |
| 6 | 切换小林查看新注册通知并标记已读 | 当前显示通知变已读 |
| 7 | 切换小周查看通知 | 小周的通知阅读状态独立 |
| 8 | 切换客户 B | 不显示客户 A 的私人会话 |
| 9 | 管理员停用测试客户，再尝试以该客户进入 | 登录被拒绝；管理员恢复后可进入 |
| 10 | 管理员调整客户为门店角色并分配门店 | 重新选择身份后展示新的角色能力 |
| 11 | 管理员修改本店名称、启停并查看审计集合 | 本地记录更新，相关操作留下审计 |
| 12 | 管理员尝试生成入口码 | 明确提示需要真实云端联调，不生成假码 |
| 13 | 管理员新增/修改/停用/删除服务、广告 | 客户重新进入首页可看到已启用内容，广告按权重排序 |
| 14 | 本地广告选择图片或视频 | 仅本机临时预览，不调用云上传；临时文件过期需重新选择 |
| 15 | 注册选择“其它”并填写位置 | 可注册并在资料页修改位置 |
| 16 | 重置演示数据 | 恢复初始五个身份及示例内容 |

本轮按一家门店验收。门店聊天已读由同店员工共享，是当前业务规则。注册通知已读则按员工独立保存。

## 演示验证的边界

- 所有演示数据只在当前设备的微信本地存储里；不同手机或模拟器之间不会同步。
- 切换身份使用重新启动页面栈，避免上一身份的页面缓存残留。
- `miniprogram/demo/service.js` 和 `domain.js` 从服务端源码生成；采用相同业务规则，替换为本地存储和非加密演示令牌。
- 修改服务端业务规则后运行 `npm run demo:sync`。静态检查会阻止演示副本与服务端规则不一致。
- 本地测试不能证明微信手机号能力、云 SDK 事务、云数据库权限、多人联机、订阅消息、支付或小程序码正常。
- 商品下单、预约、支付、履约等未实现的功能仍明确显示筹备状态。

## 反馈记录

每个发现记录：**使用身份 → 进入页面 → 操作步骤 → 实际结果 → 期望结果 → 是否影响完成服务**。
优先处理无法完成流程、串店串号、金额或状态错误；再安排易用性和视觉优化。

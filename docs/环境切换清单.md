## 本地演示 → 个人云端

1. 保存 Git 提交，运行 npm test、npm run check、npm run env:check:dev。
2. 核对开发者工具实际 AppID。共享 project.config.json 与本机 project.private.config.json 存在不同值，检查工具当前项目身份后再部署。
3. 按 database/collections.json 创建或核对十二个集合、索引与权限（含 banners、orders、settings）；每个索引的名称、字段与排序见 [上线前准备.md](上线前准备.md) 第 3 节，照抄即可。不删除旧数据，不用种子覆盖已存在的 main 门店。
4. 新环境可用 stores.seed.import.json 导入 main；stores.seed.json 提供相同记录的数组形式。门店展示名称按实际经营核定。
5. 整包上传 cloudfunctions/api 并云端安装依赖，包含 config.json 的手机号、小程序码和内容检测权限声明。
6. 仅在个人测试云函数设 DEV_LOGIN=1；前端 devLogin=true。开发/体验版通过演示页的“进入云端登录 / 联调”进入。
7. 开发期身份由手机号决定（`devActor`）：换号即换角色，一个人也能分饰客户 / 门店 / 管理员；生产环境不设 `DEV_LOGIN` 时该能力自动失效。不要将开发手机号当成经过微信验证的号码。
8. 首个业务管理员由云环境拥有者核验账号后配置；BOOTSTRAP_ADMIN_OPENID 只对首次注册有效，用完移除。店员通过业务管理员分配。
9. 多设备验证客户与员工聊天、权限变化撤销会话、通知按员工已读、服务及纯文字广告的共享更新。
10. 验证内容检测成功及故障路径。异常现在会拒绝提交；先核对权限/额度/能力，不通过静默放行掩盖配置错误。
11. 图片/视频云端上传仍待管理员专属存储授权与真机验证；保持数据库客户端禁读写和存储默认禁写，先测文字广告。本地媒体预览不能替代这项验收。

## 个人环境 → 公司环境

遵循 [环境边界与上线切换](环境边界与上线切换.md)。以干净业务数据初始化公司环境，迁移经审核的门店、服务、广告经营配置；不复制测试用户、OpenID、会话、手机号占用、聊天和测试订单。

公司标识写入 config/deployment-targets.json，再核对项目 AppID、前端 cloudEnv、主体和隐私联络方式。关闭 demoEnabled、devLogin，删除云端 DEV_LOGIN，执行 npm run env:check:prod。该脚本不检查真实云端变量，仍需人工核验。

# 环境切换清单

从「个人免费云环境」开发 → 「公司云环境」上线，照着做。

---

## 0. 先记住一句话

**云环境不能"换"，只能"重建"。但需要重建的只有结构，不是数据。**

---

## 1. 为什么不能直接换

- 微信云开发的「环境共享」官方要求**同一主体**：A 小程序的环境只能共享给**同主体**下的其他小程序 / 公众号。个人号和企业号是两个不同主体 → 这条路不存在。
- 云环境和 AppID 绑定，不支持解绑，也不支持跨账号转移。
- 所以"把个人环境换成公司的"= 在公司 AppID 下**新建一个环境**，把结构和代码铺过去。

好消息是成本很低，因为要分开看：

| 资产 | 存在哪 | 迁移动作 | 成本 |
|---|---|---|---|
| 云函数源码 | Git 仓库 | 新环境右键「上传并部署」 | 5 分钟 |
| 云函数里的环境引用 | `cloud.init({ env: DYNAMIC_CURRENT_ENV })` | **不用改** | 0 |
| 数据库结构（9 集合 + 8 索引） | `database/collections.json` | 照单重建 | 20 分钟 |
| 门店种子数据 | `database/stores.seed.import.json` | 重新导入 | 2 分钟 |
| 业务数据（用户 / 聊天 / 日志） | 个人环境 | **不要迁** | 0 |
| 前端连接配置 | `miniprogram/config.js` | 改 1 行 | 1 分钟 |

---

## 2. 关键好消息：云函数不用改代码

`cloudfunctions/api/index.js` 里是：

```js
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });
```

`DYNAMIC_CURRENT_ENV` = 「部署到哪个环境就用哪个环境」。所以换环境时**云函数代码一行都不用动**，只要在新环境重新部署一次。

前端也只有一处要改：

```js
// miniprogram/config.js
module.exports = { cloudEnv: '<环境ID>', ..., mock: false };
```

## 3. 现在：接个人云环境（开发期）

前提：已在小程序账号下创建了免费云环境。

**第 1 步 · 拿到环境 ID**

开发者工具 → 顶部「云开发」→ 环境列表里复制环境 ID（形如 `yuanlin-dev-1g1abcde`）。

> 环境名只能用小写字母、数字、中划线，不能有中文和下划线；地域选国内，别选新加坡。

**第 2 步 · 改前端配置**（`miniprogram/config.js`）

```js
module.exports = { cloudEnv: '你的环境ID', brand: '园邻', privacyOperator: '', privacyContact: '', mock: false, devLogin: true };
```

`mock` 必须同时改成 `false`，否则接口还是走假数据。`devLogin: true` 打开登录页的「开发登录」入口——个人主体没有手机号能力，必须靠它登录（详见第 4 节）。

**第 3 步 · 建 9 个集合**

云开发控制台 → 数据库 → 新建集合，按 `database/collections.json` 建齐：

```
users / phoneClaims / stores / conversations / messages
notifications / notificationReads / services / auditLogs
```

**权限必须全部选「仅管理端可读写」。** 这是本项目的核心安全设计——小程序端绝对不能直连数据库，所有读写都走 `api` 云函数。权限选错等于把数据库敞开。

**第 4 步 · 建索引**

每个集合的「索引管理」里，按 `collections.json` 的 `indexes` 建：

| 集合 | 索引字段 |
|---|---|
| users | storeId↑ + role↑ + createdAt↓ |
| users | createdAt↓ |
| stores | enabled↑ + createdAt↑ |
| conversations | customerId↑ + lastMessageAt↓ |
| conversations | storeId↑ + lastMessageAt↓ |
| messages | roomId↑ + seq↓ |
| notifications | storeId↑ + createdAt↓ |
| services | enabled↑ + createdAt↓ |
| banners | enabled↑ + weight↓ |

**第 5 步 · 部署云函数**

开发者工具左侧 `cloudfunctions/api` → 右键 → 「**上传并部署：云端安装依赖**」。

（选"云端安装依赖"，不要选"所有文件"——本地没有 `node_modules`。）

**第 6 步 · 导入门店种子数据**

数据库 → stores 集合 → 导入 → 选 `database/stores.seed.import.json`。

> ⚠️ 控制台导入有两重要求，缺一不可：**文件名必须是 `.json` 后缀**（`.jsonl` 会被拒：`invalid import filename`），**内容必须是 JSON Lines**（一行一个对象，不是 JSON 数组）。仓库里的 `stores.seed.json` 是数组格式，**别直接导它**；`stores.seed.import.json` 是专门为导入准备的（`.json` 后缀 + JSON Lines 内容）。

**第 7 步 · 设云函数环境变量**

云开发控制台 → 云函数 → `api` → 配置 → 环境变量，加两条：

```
DEV_LOGIN = 1
BOOTSTRAP_ADMIN_OPENID = 你的openid
```

- `DEV_LOGIN = 1`：打开开发期登录开关（第 4 节路线 B），允许登录页用测试手机号注册/登录。**只在个人联调环境设，公司生产环境绝不设。**
- `BOOTSTRAP_ADMIN_OPENID`：指定第一个管理员——这个 openid 注册时会自动成为管理员。

拿自己 openid 的办法：开关开启后，云函数会把每次调用者的 openid 自动打进运行日志。先用「开发登录」注册一次，然后去「云函数 → api → 日志」里找 `dev caller openid:` 那一行，复制过来填进环境变量，**重新部署一次云函数让变量生效**，再登录一次就是管理员了。

**第 8 步 · 走一遍**

参考 `docs/开工指南.md` 第三节，三个身份各点一遍。

**第 9 步 · 三个人的配置别互相踩**

AppID 和云环境 ID 都是"每人一份"的东西，但仓库只有一份代码。分开放：

| 配置 | 放哪 | 会不会进 Git |
|---|---|---|
| **AppID** | `project.private.config.json` | **不会**（`.gitignore` 已忽略） |
| 云环境 ID | `miniprogram/config.js` 的 `cloudEnv` | **会**（三个人会互相覆盖） |

**AppID 的正确放法**

项目根目录的 `project.private.config.json` 里放自己的 AppID，它的优先级**高于** `project.config.json`：

```json
{ "appid": "你自己的AppID" }
```

好处是：改它不影响别人、不污染仓库，将来上线时把公司 AppID 写进 `project.config.json` 也不会被某个人本地的值盖住。

> 官方文档原话：`project.private.config.json` 中的相同设置优先级高于 `project.config.json`；若私有文件里已有 `appid` 字段，在「详情 → 基本信息」里改 AppID 会写进私有文件，**不会覆盖** `project.config.json` 里的 `appid`。

⚠️ 接手别人代码时的高频坑：改完 AppID，模拟器还是显示旧的。原因是工具有缓存。处理顺序：关掉工具 → 删掉旧的 `project.private.config.json` 里的 appid 值 → 重新打开 → 详情里确认。还不对就「工具 → 清除缓存 → 清除全部缓存」。

**云环境 ID 的推荐做法**

**统一用一个开发 AppID + 一个云环境。** 另外两个人让管理员加成「项目成员」（个人主体最多可绑 15 个项目成员，够用）。理由：配置只有一份不会互相覆盖，数据也共享——聊天功能至少要两个人才能测，各用各的环境根本联调不了。

如果确实要各用各的环境，那就只能约定：**改 `config.js` 之前先跟另外两人说一声，改完不要提交这个文件**（或本地用 `git update-index --skip-worktree miniprogram/config.js` 跳过跟踪）。这比统一环境麻烦得多。

## 4. 个人主体的硬限制：拿不到手机号

**这一条会让你们在第 8 步卡住，必须提前知道。**

微信官方文档（手机号快速验证组件）原文：

> 目前该接口针对**非个人主体**，且完成了认证的小程序开放。

而本项目的注册登录**完全依赖**这个能力：登录页按钮 `open-type="getPhoneNumber"` → 拿到 code → 云函数调 `cloud.openapi.phonenumber.getPhoneNumber`。

所以现在的真实状态是：

| 能验证 | 不能验证 |
|---|---|
| 云函数逻辑、数据库事务、索引、权限、并发 | **注册登录流程**、真机预览、代码上传、支付 |

三条路，任选：

| 路线 | 做法 | 代价 |
|---|---|---|
| A. 等公司账号 | 公司 AppID 和认证下来后，直接在公司环境开发 | 空等（认证 1–3 天，备案更久） |
| **B. 开发期登录开关（已实现 ✅）** | 云函数环境变量 `DEV_LOGIN=1` 时，登录页可用测试手机号注册/登录 | 前端 `config.js` 开 `devLogin` + 云函数设环境变量，两处一起 |
| C. 继续用 mock | `mock: true`，走内存假数据 | 验证不了真云环境的坑 |

**建议 B + A 并行**：现在用开关打通全流程，公司账号到位后直接切，开关在生产环境永不启用。

### 路线 B 的用法（已实现，照做即可）

1. 云函数 `api` 的环境变量加 `DEV_LOGIN=1`（第 7 步）；
2. 前端 `config.js` 设 `devLogin: true`（第 2 步）；
3. 登录页会出现「开发登录」入口：输入任意 11 位测试手机号即可注册/登录，**不同手机号 = 不同账号**——三个人各用一个号，就能联调聊天；
4. 要当管理员的人：先注册一次 → 云函数日志里拿自己的 openid（`dev caller openid:`）→ 填进 `BOOTSTRAP_ADMIN_OPENID` → 重新部署云函数 → 再登录一次即是管理员；
5. 门店身份没有捷径：先注册成客户，再由管理员在「管理中心 → 用户」里改成门店员工。这和真实运营流程一致，顺手把管理后台也测了。

### 这个开关的安全边界（为什么敢开）

- **判断在服务端**（云函数环境变量），前端开关只控制入口显示。生产环境不设 `DEV_LOGIN`，就算前端传 `dev:` 凭证，也会被当成普通 code 走真实手机号验证；
- 开关只跳过「手机号验证」这一步：手机号格式（`/^1\d{10}$/`）、一机一号绑定（`phoneClaims`）、停用门店/账户拦截、角色分配（`BOOTSTRAP_ADMIN_OPENID`）全部照常执行；
- **前端无法指定角色**——开关开着，注册出来也只是客户；门店/管理员身份只能由管理员在后台调整；
- 以上行为由 `tests/service.test.js` 的专门用例守住（"dev login switch"），改坏了 `npm test` 会拦。

## 5. 上线日：切到公司环境

照着第 3 节整体重做一遍，然后改三处配置：

| 文件 | 改什么 |
|---|---|
| `project.config.json` | `appid` → 公司 AppID |
| `miniprogram/config.js` | `cloudEnv` → 公司环境 ID |
| `miniprogram/config.js` | `privacyOperator` / `privacyContact` → 公司信息（隐私协议主体） |

改完：重新编译 → 三个身份各跑一遍 → `npm test` + `npm run check` → 提审。

## 6. 什么能迁、什么不能迁

| 数据 | 迁不迁 | 原因 |
|---|---|---|
| 集合结构、索引 | **必须建** | 结构不是数据，重建约 20 分钟 |
| 门店 stores | 重新导 | 种子数据，重新导更干净 |
| 服务 services | 重新录 | 数量少 |
| 用户 users | **不要迁** | openid 变了，迁过去全是死账号 |
| 聊天 conversations / messages | **不要迁** | 同上，且是测试内容 |
| 手机号占用 phoneClaims | **不要迁** | 同上 |
| 通知 notifications / notificationReads | **不要迁** | 测试噪音 |
| 审计日志 auditLogs | **不要迁** | 测试噪音 |
| 云存储文件 | 现在没有 | 项目还没做图片功能 |

**为什么用户迁不了？**

- `openid` 由 AppID 决定。换 AppID 后，同一个人的 openid 完全不一样。
- `unionid` 只在**同一个微信开放平台账号**下才一致。个人号和企业号不共用开放平台账号，所以连 unionid 都对不上。
- 结论：**跨主体没有可靠手段把"同一个真人"关联起来。** 这不是技术问题，是设计如此。

## 7. 测试期三条纪律

1. **只用你们三个人 + 体验成员测**，不要让园区真实用户注册——上线时这些账号全部作废。
2. 真要给真实用户试用，**提前说清"正式上线后需要重新注册"**，别让人以为账号会延续。
3. **别往测试环境录真实客户信息**（姓名、手机号）。环境挂在个人账号名下，数据归属不清晰，也涉及个人信息合规。

## 8. 钱的提醒

- 免费云环境是官方活动：每个小程序账号可创建 1 个，**开发阶段无需续费**，配额与基础套餐一致（不支持额外加购）。
- ⚠️ **小程序发布上线后，免费环境的到期时间变更为"上线后第 15 天"**，之后需要转付费或销毁。把这条写进上线 checklist。
- 个人环境如果不再使用，去控制台**注销**，避免继续占用资源。
- 付费起步档位参考 19.9 元 / 月（以控制台实时价格为准）。

# 架构与扩展

## 信任边界

`小程序页面 → utils/api → api 云函数 → service → repository → 云数据库`

服务端使用 `cloud.getWXContext().OPENID` 标识微信用户；不接受客户端提供的角色或 OpenID。手机号仅来自云调用兑换的临时 code。验证后产生随机会话令牌，仅哈希持久化到用户记录，所有敏感接口重新检查用户有效状态、角色、期限与门店状态。

首次注册用用户确定性 ID 和手机号唯一占用文档，在同一事务中写用户、占用、注册通知。重复注册不会再生成通知。消息使用 `发送者+会话+requestId` 的哈希 ID 做幂等；同一事务更新消息、会话序号和发送频率标记。未读采用单调序号，避免“读到第1条”把同时到达的第2条误标为已读。

## 数据集合

| 集合 | 用途 | 主要字段 |
|---|---|---|
| users | 注册资料与角色、会话 | nickname, phone, park, gender, role, storeId, enabled, sessionHash, sessionExpiresAt |
| phoneClaims | 手机号唯一占用 | `_id=SHA256(区号:手机号)`, userId |
| stores | 门店基础信息 | name, enabled |
| conversations | 客户/门店会话 | customerId, storeId, sequence, customerReadSeq, storeReadSeq, lastText |
| messages | 有序文字消息 | roomId, senderId, senderRole, content, seq |
| notifications | 新注册通知 | storeId, customerId, nickname, park |
| notificationReads | 按员工的通知已读位置 | `_id=userId`, readAt |
| services | 后续服务介绍卡片 | name, category, description, enabled |
| auditLogs | 管理变更及数据查看 | actorId, action, target, detail |

业务时间用服务端毫秒时间戳，字段统一 `createdAt/updatedAt`；未来价格统一整数分。小程序端不能直接读写集合。

## 权限

| 能力 | 客户 | 门店 | 管理员 |
|---|---|---|---|
| 修改自身非敏感资料 | 是 | 是 | 是 |
| 与归属门店聊天 | 是 | 本店客户 | 只读审计 |
| 客户资料 | 自己 | 本店客户 | 全部 |
| 新注册通知 | 否 | 本店 | 全部 |
| 账户启停、门店角色分配 | 否 | 否 | 是 |
| 门店管理、入口码 | 否 | 否 | 是 |
| 后台数据库分页查看 | 否 | 否 | 白名单集合 |

不提供前端“切换成管理员”或硬编码测试账号。管理员角色只由云项目拥有者引导建立。用户角色修改会清空会话。

## 后续服务模块

当前首页分类保留 `laundry` / `housekeeping` 两个稳定类别；`services.list` 返回可用服务介绍。后续新增管理端服务编辑、详情页后可复用此表。

建议按模块增加 `modules/catalog.js`、`modules/orders.js`、`modules/bookings.js`、`modules/payments.js`，在 `service.js` 中统一身份校验后路由，复用事务和审计接口。订单参数/状态合同已放在 `modules/order-contract.js`，但没有对外开放订单 API，避免内容未定时产生不可履约订单。

订单建议独立维护：`orders`（客户、门店、服务快照、金额分、状态）、`orderEvents`（状态变更）、`bookings`（预约时间段、容量）、`payments`（支付回调及退款幂等）、`addresses`（后续确认是否需要楼栋房间）。价格、优惠及总价必须在服务端计算，支付结果只认可信回调。

洗护可扩展取送时间、衣物清单与交付核验；家政可扩展预约时长、服务人员和核销。聊天沿用现有客户-门店关系，可在后续消息类型中增加订单引用，不要把订单状态依赖于文字内容。

离线提醒需新增订阅记录和可靠通知任务表。客户注册事务先写通知任务，单独投递任务发送并记录成功/失败重试，不能因订阅失败回滚用户注册。管理员不得替员工授权订阅。

若上线面向大量公众，应扩展服务端消息内容安全检查、投诉处理、云资源监控和按平台要求配置的留存/清理策略。附件应另设私有存储权限与引用校验，不能复用公开入口码路径。

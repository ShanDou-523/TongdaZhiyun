# 开工指南

给三位开发者：从哪入手、今天做什么、什么不用管。

---

## 一、先止住焦虑：你们想同时抓住六件事

账号 → 认证 → 备案 → 类目 → 工具 → 代码。这里面**只有最后一件事是你们的**，前五件都在企划部和老板那边跑，你们盯着它们只会干等。

所以从今天起，分两条线看：

| 谁在推 | 推什么 | 你们要做什么 |
|---|---|---|
| 企划部 / 老板 | 注册、认证、备案、商户号 | 什么都不用做，偶尔被问就答 |
| **你们三个** | **开发和调试** | 从下面第一步开始 |

**代码可以等账号，账号不用等代码。** 而且我已经把这条路打通了——现在不依赖任何账号就能开发。

---

## 二、第一步：把项目跑起来（每人做一遍，约 20 分钟）

1. 装 **Git**：`git-scm.com` 下载，一路下一步
2. 装 **微信开发者工具**（稳定版）
3. **把代码弄到本地**，两种方式选一个：
   - 命令行：`git clone https://github.com/ShanDou-523/TongdaZhiyun.git`
   - 或者让同学把仓库打包成 zip 发你（最快，但暂时不能 git 协作）
4. 打开开发者工具 → 左侧选「小程序」→「**导入项目**」
   - **目录**：选仓库**根目录**（能看到 `project.config.json` 的那层）
   - **别选内层的 `miniprogram` 文件夹**，选错了一定会报错
   - **AppID**：先保持不动，直接确定（用演示模式跑界面不依赖 AppID）
   - 等你要接**自己的云环境**时，再把 AppID 换成自己的——改法见 `docs/环境切换清单.md` 第 9 步（放 `project.private.config.json`，不会影响别人）
5. 看左边模拟器

**成功的样子**：出现「园邻」的绿色登录页，页面上有**三个按钮**——「以客户进入 / 以门店进入 / 以管理员进入」。

看到这三个按钮，就说明你的环境通了。看不到，就是第 4 步目录选错了。

---

## 三、第二步：把三个身份都点一遍（约 30 分钟，做完就不懵了）

这一步是给你们建立"这项目到底长什么样"的直觉，比看任何文档都管用。

**以客户进入**
- 首页 → 点「发消息给门店」→ 发一条消息 → 返回

**我的 → 退出登录 → 以门店进入**
- 底部「消息」→ 应该看到刚才那条未读 → 点进去回复

**退出登录 → 以管理员进入**
- 首页 → 点「进入管理中心」
- 切到「**服务**」标签 → 填一条新服务 → 保存
- 回到首页往下拉 → **刚加的服务出现了**
- 回管理中心 → 把它停用 → 首页就看不到了 → 删掉

**顺便**：全程盯着右边的 Console 面板，应该一条红字都没有。

> 这个小程序是**客户 / 门店 / 管理员三种角色共用同一个 App，按角色显示不同界面**。把三个身份都走一遍，你就理解了整个产品结构。

## 四、为什么现在就能跑通？（这不是假的 UI）

项目里加了一个开关，在 `miniprogram/config.js`：

```js
mock: true    // 所有接口走 miniprogram/mock/ 里的内存假数据
mock: false   // 接口走真实云函数
```

- `utils/api.js` 是**唯一**的切换点。页面代码一行都没改，也不会因为切换而改。
- 演示数据在内存里，**重启小程序就恢复初始状态**，随便点随便删，点坏了没关系。
- 假数据里预置了 3 家门店、3 个用户、2 项服务，故意留了一家停用门店和一个越权场景，方便看到错误提示。

⚠️ **联调真实云函数或提交审核前，必须把 `mock` 改回 `false`。**

## 五、第三步：分工

业务方向定死之后再锁人，现在先按技术层次分，谁擅长什么领什么：

| 方向 | 从哪里入手（第一件事） | 涉及文件 |
|---|---|---|
| **前端页面** | 首页那两张写着"筹备中"的卡片改成动态渲染 | `pages/home/` |
| **后端云函数** | 给聊天加内容安全检测（UGC 小程序提审必查，没有必被驳回） | `cloudfunctions/api/service.js` |
| **后台 + 数据** | 把 `database/collections.json` 里的集合和索引在云环境里建好 | `database/`、`pages/admin/` |

**三个人都要守的三条纪律：**

1. **改完必跑 `npm test`**（现在 26 个用例）。跑不过就是改坏了，别往下走。
2. **一次只做一件事。** 一口气要 5 个功能，出错了根本不知道是哪一步坏的。
3. **改完就 commit。** 一次提交对应一件事，坏了好回退：
   ```bash
   git add -A && git commit -m "说明这次做了什么" && git push
   ```

**跟 AI 提需求时，四要素别省：**

```
【目标】管理后台加服务管理 tab
【已有的】services 集合已存在，字段 name/category/description/enabled
【约束】写操作包事务、权限用 admin(user)、输入过 text() 校验、记 audit
【验收】npm test 全过，npm run check 全过
【别动】不要改 project.config.json 的 appid，不要碰支付代码
```

## 六、现在明确不用管的事

| 事项 | 归谁 | 什么时候需要你们 |
|---|---|---|
| 小程序账号注册 | 企划部 | 拿到 AppID 时 |
| 微信认证 300 元 / 年 | 企划部 / 老板 | 不需要 |
| ICP 备案 | 企划部 | 提审前 |
| 云开发环境 | 你们 | 可以用**个人免费环境**开发（开发期免费）；但云环境**不能跨主体迁移**，上线时要在公司账号下重建（约 40 分钟）——见 `docs/环境切换清单.md` |
| 服务类目与行业资质 | 老板拍板 | 提审前 |
| 微信支付 | 老板确认方向 | **方向没定之前不碰** |
| 商户号申请 | 企划部 | 确定要做交易再说 |

## 七、一句话总结

**别等，先把三个人电脑上的项目跑起来，把三个身份各点一遍。** 做完这件事，你们后面所有关于"从何入手"的问题都会自己消失——因为你们见过它跑起来的样子了。

需要更细的说明看 `docs/开发手册.md`（项目地图、增删改查怎么做、优化清单）。

要接真实云环境（开发期用个人免费环境、上线切公司环境），照 `docs/环境切换清单.md` 走——里面也写清了为什么云环境只能重建不能迁移。

# 园邻 · 园区生活服务小程序

原生微信小程序 + 微信云开发。暂定产品名“园邻”，可随时改名。客户、门店和管理员共用一个小程序，通过后端账户角色显示不同工作台。

## 无手机号快速体验

当前已开启本地演示。重新编译后进入身份选择页，客户、一家门店员工和管理员均可一键进入。页面顶部可切换身份，演示入口可新增客户和重置数据。开发版/体验版可用，正式版禁用。

演示数据保存在当前设备，不会同步到其他手机；真实手机号、云端事务、支付和入口码仍需单独联调。详细步骤见 [本地演示与功能验收](docs/本地演示与功能验收.md)，洗护和家政的完整推进范围见 [开发推进计划](docs/开发推进计划.md)。

## 已实现

- 门店小程序码：`pages/auth/index?scene=s%3Dmain`，扫码携带门店编号；未登录进入注册/登录，已有有效登录态进入首页，不改变已有客户归属。
- 注册资料：昵称、微信验证的大陆手机号、一至十一园区、青教公寓、其它（补充具体位置）、性别（可选不愿透露）。正式登录使用微信手机号验证；个人云环境可开启开发登录，本地演示支持直接选择身份。
- 客户：服务首页、资料编辑、联系所属门店、文字聊天、历史消息分页及未读状态。
- 门店：本店客户列表、主动发起对话、近期新客户注册提醒与已读管理。
- 管理员：客户/员工管理、停用/启用账户、分配门店角色及归属、门店管理、服务和广告管理、生成入口码、数据库只读分页查看、管理操作审计。
- 服务扩展：洗护/家政入口、`services` 数据接口、独立订单状态/参数合同和后续模块设计。

**本地源码版本，云端部署与发布状态尚未验证。** 已填写 AppID 和云环境；本地演示使用独立测试身份，个人云端可使用开发登录（不校验号码归属）。真实业务需要按下列步骤连接云开发。微信开发者工具中使用游客 AppID 只能查看页面，不可验证云端业务。

个人云端联调与公司切换见 [环境切换清单](docs/环境切换清单.md)。图片/视频广告已合入代码和本地预览，真实上传尚待管理员专属存储授权；不要开放全局客户端写入。

## 1. 配置项目

1. 用微信开发者工具导入本目录。核对 `project.config.json` 中已配置的 AppID 是否属于目标小程序。
2. 当前 `miniprogram/config.js` 的 `cloudEnv` 为 `cloudbase-d9g2aibtdf3e4d6bc`，请确认该环境关联目标小程序。
3. 在同一文件填写 `privacyOperator`（运营主体）、`privacyContact`（真实隐私联络方式）。在微信公众平台配置《用户隐私保护指引》，覆盖手机号、资料、聊天等实际处理内容，并确认手机号能力可用。页面隐私文案是开发草稿，需要运营方核定。
4. 登录微信开发者工具。手机号授权需通过支持该能力的真实微信客户端检验；费用与主体资格以公众平台当前能力状态为准。

前端不需要 AppSecret，不要把任何密钥写进小程序。

## 2. 创建数据库

在**选定的云开发环境**中逐一创建 `database/collections.json` 列出的10个集合。

所有集合均使用 `database/permissions.json`：禁止小程序端直接读写。所有访问走 `api` 云函数，云函数在服务端校验身份、会话和角色。不要使用“所有用户可读写”的开发权限。

按清单创建复合索引；管理端可查询集合需按 `createdAt` 降序读取。该 JSON 为人工部署清单，不会自动创建集合或索引。

在 `stores` 集合创建初始记录（可参考 `database/stores.seed.json`）：

```json
{"_id":"main","name":"园区服务中心","enabled":true,"createdAt":0,"updatedAt":0}
```

不要在真实环境重复导入覆盖已有门店。

## 3. 部署云函数

在微信开发者工具中右键 `cloudfunctions/api`，选择“上传并部署：云端安装依赖”，确认目标云环境。服务端依赖锁定在该目录的 `package-lock.json`；本地安装可运行 `npm ci --ignore-scripts`。前端没有 npm 依赖，不需要“构建 npm”。

云函数建议采用当前云平台支持的 Node.js 18 或更新兼容运行时、256MB 内存、20秒超时。`config.json` 声明手机号、小程序码和文字内容检测云调用权限，必须一并部署。若调用失败，检查云环境是否关联正确小程序及该 API 能力是否已开通。

云存储用来保存门店入口码。保持客户端不可写，图片只含公开门店编号。管理员通过临时地址查看；若默认存储规则不允许读取云函数生成的文件，可对 `entry-codes/` 单独允许读取，仍禁止客户端写入，其他路径保持受限。

## 4. 建立首个管理员

推荐方式：先完成数据库和云函数部署，自己在小程序通过手机号注册；然后由有云控制台权限的项目拥有者，在 `users` 集合中找到自己的已验证手机号记录，仅将 `role` 从 `customer` 改为 `admin`。重新登录后出现管理中心。

可选方式：若已准确知道自己的微信 OpenID，可在首次注册前设置云函数环境变量 `BOOTSTRAP_ADMIN_OPENID` 为该 OpenID。只有该身份第一次注册才被初始化为管理员。初始化后移除此环境变量。普通客户端没有授予管理员角色的接口。

不要把其他用户设置为管理员来充当门店。门店员工先以普通用户完成手机号注册，再由管理员在“账户”中分配“门店”角色和门店归属。权限修改会撤销该用户已有会话，要求重新验证手机号。

## 5. 生成可用入口码

管理员 → 管理中心 → 入口码 → 门店与版本 → 生成。正式码要求对应页面已发布。体验版/开发版需要相应版本与体验权限；生成图片不等于已发布小程序。

本地“门店扫码入口”编译条件预设 `scene=s%3Dmain`。普通链接/第三方二维码不能仅靠本项目自动转换成微信可识别的小程序码；如已有普通二维码，需要提供其内容并按平台规则配置跳转。

官方入口：[CloudBase 带参小程序码](https://docs.cloudbase.net/recipes/add-share-with-params-miniprogram)、[微信手机号能力](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/getPhoneNumber.html)。

## 功能边界

- 地址保存园区选项；选择“其它”时可补充20字位置描述。另提供选填宿舍号（最多20字），可在资料页修改或清空。尚未建立完整服务地址模型，不采集定位。
- 默认单个客户/员工归属一个门店。改变归属后，新会话属于新门店，旧会话保留历史归属；客户仍可读写其旧会话，原门店仍可查历史会话。若不希望客户继续联系原门店，可在后续业务规则中改成只读归档。
- 新注册通知与用户记录使用同一事务保存。门店工作台打开时约15秒轮询，显示最近20条通知；仅将已显示通知按员工标记已读，更早未显示的通知保持原状态。**未接入退出小程序后的微信订阅推送**，后续须选择合适模板并由员工主动授权。
- 会话页约4秒轮询，消息列表约15秒轮询，隐藏页面停止轮询。当前为文字聊天；未启用图片、语音、支付和接单。
- 手机号与微信身份绑定，重复手机号不会自动合并账号。换绑、注销和数据删除目前由运营方通过云控制台审慎处理，先核验本人身份。移除账户时同步处理手机号占用记录、会话资料和留存规则。
- 登录有效期7天；主动退出、停用或权限变更会撤销会话。重新验证会撤销旧令牌。
- 数据库查看为管理员只读、每页20条，隐藏会话哈希和手机号占用集合；其他数据库操作由云控制台执行。
- 门店选择最多返回100家；管理员分页上限10000页。规模扩大前应加入服务端搜索与游标分页。
- “筹备中”入口不会创建虚假订单。`services` 可配置已启用的介绍卡片用于咨询，管理员可维护介绍卡片；规格、价格和下单仍待开发。

## 开发与测试

```powershell
npm test
npm run check
```

使用 Node.js 18+ 的内置测试框架，无需安装测试依赖。测试在内存事务仓库执行，覆盖身份/权限隔离、手机号绑定、会话撤销、重复注册、重复发送、已读、历史分页和事务回滚；不替代真实云数据库事务测试。`docs/验收清单.md` 列出真机检查项。

目录说明：

```text
miniprogram/          页面、样式、微信 API 调用
cloudfunctions/api/   服务端入口、业务规则、可信仓库适配器
database/            集合、权限、索引及初始门店示例
tests/               本地业务及页面行为测试
docs/                架构、扩展与验收说明
scripts/check.js     语法、JSON 和页面配置验证
```
